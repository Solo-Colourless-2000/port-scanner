# セキュリティエンジニア面接用：ポートフォリオ説明準備

この教材は面接で話すための題材を提供しますが、**ユーザー自身が実施していないことを実績として記載するものではありません**。原典サンプルやAI作成の見本をそのまま自作だと称してはいけません。

## 5分の説明の組み立て

1. **課題**：運用中のネットワークの問題を調査する際に、「接続できない＝ポートが閉じている」と断定すると誤る可能性がある。何を観測したいのかを明示する。
2. **対象と安全な範囲**：ポート番号・IPv4リテラル・CIDR・loopback限定・手作業の許可確認など、どの誤操作を防ごうとしたかを示す。
3. **設計**：入力検証 → ソケット接続 → OSエラーの分類 → JSON出力。成功・接続拒否・タイムアウトを分け、残る曖昧さも説明する。
4. **自分が担当した部分**：学習見本と自分で実装した新機能を区別し、Gitのコミットとテスト差分を示す。実装していない機能を紹介しない。
5. **検査の証拠**：loopbackサーバ起動前・起動中・終了後で結果を比較。実際のOS・Python版、テスト実行結果、日時を明示する。
6. **改善余地**：タイムアウト、OS差異、許可の手動確認、サービスの可用性への影響、運用時のログ管理など、保証できないことを説明する。

## 想定質問と準備すべき証拠

| 質問 | 用意する具体的な説明・資料 |
|---|---|
| なぜNmapではなく小さなPythonツールを作ったか | Nmapの代替ではなく、TCP接続・errno・対象制限・テストを自分で理解する教材だという位置付け |
| `ECONNREFUSED` とタイムアウトの違いは | 何を観測し、何を観測できないか。実際のloopback結果と、通信経路の影響の例 |
| なぜ`--authorized`だけでは十分でないか | フラグは自己宣言であって権限確認ではない。書面による対象・日時の承認が別途必要 |
| どこからが自分の実装か | サンプルとの差分とコミット、試験記録。共同作業・支援の範囲も含めて正確に区分 |
| どうテストしたか | 正常系・不正入力・スコープ逸脱・実ソケットの開閉、CIと手動の区別 |
| セキュリティ上の残余リスクは | 実際の承認判定はソフトウェアではできないこと、結果JSONの情報漏えい、OS依存のerrno |

## 提出の前に

* 5分程度で「目的、判断、実装差分、テスト、失敗、改善」を読み上げずに説明できるか練習する。
* 動画やスクリーンショットは**自分で実際に検証したものだけ**を使う。
* 原典コードを大量転載した場合の許諾、第三者のAPI・依存の利用条件、会社データの持ち出し禁止を確認する。
* 「ペネトレーションテストツール」と過大評価せず、「安全な対象制限付きTCP接続観測CLI」と正確に説明する。

「ネットワーク監視では、単にポートが開いているかだけでなく、いつどのポートの接続状態が変わったかを根拠付きで整理することが重要だと考えました。そこでTCP観測結果のJSONを読み、同じIP・同じ対象ポート・同じ範囲で測定した結果だけを差分として扱うオフラインの比較処理を学習しました。レポートの重複キーや破損JSON、時刻の逆転もテストで拒否しています。ただし観測状態の変化は脆弱性の存在を証明するものではありません。」

上は**学習した見本の説明**です。自分で実装しなかった処理について「自作した」と言い換えないでください。提出時は具体的に自分が改修した追加機能、コミットSHA、テストの失敗と修正、検証日時を添えて説明を完成させます。
