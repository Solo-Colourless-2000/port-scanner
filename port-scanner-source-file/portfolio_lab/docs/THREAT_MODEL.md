# 簡易脅威モデル

| 資産・境界 | 想定される誤用・失敗 | 軽減策 | 残る問題 |
|---|---|---|---|
| 検査対象のネットワーク | 対象を間違え、他人のサービスへ接続 | デフォルトloopback、IPv4リテラルのみ、RFC1918 /24以下の明示範囲 | 実際の管理者承認まではソフトウェアでは判定できない |
| 対象サービスの可用性 | 多数接続で負荷を与える | ポート数最大32、直列、各ポート0.1〜3秒 | 低負荷の保証ではなく、環境によって1接続でも影響がある |
| 検査レポート | 内部IPや構成の漏えい | ログをGit管理から除外、公開前に手動確認 | ユーザーが別名で保存すればGitに追加できる |
| 結果の解釈 | 応答なしを『閉鎖/安全』と断定 | refused / timeout / unreachable / error を区別 | パケットキャプチャなしでは原因を確定できない |
| 依存関係 | ライブラリ導入時の供給元リスク | Python標準ライブラリだけを使用 | OSとPythonの更新確認は必要 |

**公開前に実施すること**：個人の端末名、社内IP、資格情報、実組織を特定する情報、許可されない診断ログはアップロードしない。検証対象は自分のloopbackまたは書面で許可された隔離ラボに限定する。

## レポート比較機能の追加リスク

- **不正な入力**：巨大なJSON、重複キー、予期しない型、未知の状態名を読み込む可能性。入力サイズ・型・値を制限し、拒否するテストを付ける。
- **不適切な比較**：IP・ポート集合・scope・日時が異なる2レポートを誤って比較して結論を出す可能性。これらの一致・前後関係を検証する。
- **機密性**：入力JSONには対象IPv4、ポート、時刻が含まれる。公開リポジトリへ誤って含めない。
- **入力の真正性**：JSONの形式検証は実際の収集方法や改ざんの有無を証明しない。署名や収集端末の証拠はこの見本にない。
- **保存の完全性**：出力をexclusive-createして上書きは防ぐが、途中書込失敗の原子的復旧は実装していない。
- **非目的**：ポート状態の差分をCVEや侵入の根拠として断定しない。
