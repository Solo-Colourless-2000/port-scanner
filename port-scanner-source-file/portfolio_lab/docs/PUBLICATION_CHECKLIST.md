# GitHub公開・応募前チェックリスト

- [ ] 原典READMEの「サンプルコード」利用条件を読み、転載箇所と自作箇所を分離した。
- [ ] 本サンプルから自分で設計・実装した改良点を明示できる。
- [ ] コードに秘密情報、固定パスワード、実組織のIP、トークン、SSH鍵はない。
- [ ] `.gitignore` に依存せず、`git diff --cached` でステージ済みファイルを確認した。
- [ ] `python3 -m unittest discover -s tests -v` の結果と実行環境を記録した。
- [ ] ローカルHTTPサーバーの起動→スキャン→停止→再スキャンを実施し、差分を記録した。
- [ ] 報告された `refused`・`timeout` の意味と限界を説明できる。
- [ ] CIが対象ネットワークを走査せず、自ホストのloopbackだけを使うことを確認した。
- [ ] 設計図、脅威モデル、制約事項、再現コマンド、検証記録を揃えた。
- [ ] LICENSEを採用する場合は、本人が権利を持つ自作部分だけに適用した。
- [ ] 著作権表示と使用した参考資料、具体的な貢献範囲をREADMEに記載した。
- [ ] READMEのスクリーンショットは権限のある環境で撮り、個人情報を消した。
- [ ] 面接では「学習した点 / 自分で改善した点 / 失敗 / 修正 / 検証」を具体例で話せる。

## 比較ツールを公開する場合の追加チェック

- [ ] `before.json`、`after.json`、`difference.json` を公開する理由があるか検討し、不要ならコミットしていない。
- [ ] 同じtarget・scope・ポート集合・時間順序を検証する仕様と限界を説明している。
- [ ] `report_diff.py` がネットワーク通信を行わないことと、入力の信頼性までは保証しないことを区別している。
- [ ] 今回の見本と、自分が実際に設計・追加したコードをGit履歴とREADMEで区別している。
- [ ] 原典のREADME「サンプルコード」の利用条件と、自作コードのライセンスを混同していない。
