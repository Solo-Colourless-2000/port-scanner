## 行単位での設計上の判断

### `portfolio_lab/report_diff.py`

- **入力スキーマの完全一致**：トップレベルは `timestamp_utc` / `target` / `scope` / `timeout_seconds` / `results` の5キー、各結果行は `port` / `state` / `errno` の3キー。`set(report) != required_report_fields` は**キー集合の完全一致**を要求するので、欠落と未知のキーをどちらも拒否する。値の正しさは後続の別判定で確認する。
- **集合差**：`required_report_fields - report.keys()` は欠落、逆向きの差は未知キー。これらは対称差とは異なる。`sorted()` で再現可能なエラーメッセージを作る。
- **単一ファイル検証**：`--validate` は `read_report` に1件のローカルJSONを渡すだけ。TCP接続を試みるコードは含まれない。報告書の形式や内部整合性が妥当という表示であり、データが改変されていない、署名済み、実測であることの証明ではない。
- **比較引数との排他**：`--before` と `--after` はセット。`--validate` はこれらや `--output` と混在できず、エラーメッセージと終了コード2を返す。
- **既存の限界**：`state` が `refused` で `errno` が非ゼロでも、`errno` が実行OSの `ECONNREFUSED` と同値かまでは比較ツールは検証していない。OS間でエラー番号が異なり得るためで、形式検証を全状態の観測事実の証明と捉えないこと。

### `portfolio_lab/tests/test_report_diff.py`

- 正規のレポートを保存し、未知キー・必須キー欠落・結果行の余分キー・結果行の必須キー欠落を `subTest` でテストする。
- `subprocess.run` でCLIを実際に呼び、正常時の `VALID` と終了コード0、異常時の診断と終了コード2、単独検証がファイルを新規作成しないことを確認する。
- `TemporaryDirectory` は外部ファイルを破壊せずに失敗を再現するための仕組み。異常系テストは第三者ネットワークに一切接続しない。
